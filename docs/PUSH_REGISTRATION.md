# 通知の登録

新しい文書が追加されたときにスマートフォンへ通知が届くようにします。端末ごとに1回ずつ行います。

---
<br/>
<br/>

## 仕組み
アプリは文書リポジトリへ書き込みません。アプリのアクセストークンを「読み取りだけ」に保つためです。

そのため、端末で作った購読情報を、あなたがワークフローへ貼り付けて登録します。手間はかかりますが、万一トークンが漏れても文書を書き換えられる恐れがなくなります。

```text
[端末] 通知を有効にする
   ↓ 購読情報のJSONを作る
[あなた] コピーしてワークフローへ貼り付ける
   ↓
[文書リポジトリ] .app/push-subscriptions.json へ保存
   ↓ 新しい文書が追加されたとき
[端末] 通知が届く
```

---
<br/>
<br/>

## 登録する
### 1. 端末で購読を作る
1. アプリを開いて設定 →「通知の設定」
2. 端末名を入れる（例：`Pixel`、`iPhone`）。どの端末かを見分けるためだけに使います
3. 「通知を有効にする」を押す
4. ブラウザの許可ダイアログで「許可」を選ぶ
5. 表示されたJSONの「登録JSONをコピー」を押す

iPhone・iPadでは、ホーム画面に追加したアプリとして起動していないとボタンを押せません。`docs/IOS_INSTALL.md` を参照してください。

### 2. ワークフローで登録する
1. 同じ画面の「登録ワークフローを開く」を押す（PCで開いても構いません）
2. 「Run workflow」を押す
3. `label` に端末名、`subscription_json` にコピーしたJSONを貼り付ける
4. 「Run workflow」で実行する

数十秒で完了します。`.app/push-subscriptions.json` が更新されれば成功です。

### 3. 届くか確かめる
1. Actions →「Send test push」→ Run workflow
2. 端末に「通知のテストです。受信できています。」と届けば成功

## 通知に含まれる情報
プライバシーのため、通知には次しか含めません。

```text
タイトル：catch-up-docs
本文：新しいドキュメントが追加されました。
```

複数件のときは「新しいドキュメントが3件追加されました。」となります。

**文書の題名、ファイル名、リポジトリ名、本文は含まれません。** ロック画面に通知が出ても、中身が分からないようにするためです。

通知をタップするとアプリが開きます。ロックされていればパスワード入力が出て、解除してから対象の文書が開きます。

## 台数の上限
登録できるのは5台までです。上限に達した状態で登録しようとすると、ワークフローが失敗します。使わなくなった端末を削除してください。

同じ端末を再登録した場合は上書きされます。台数は増えません。

## 解除する
端末側とリポジトリ側の両方で行います。片方だけだと、届かない通知を送り続けることになります。

### 端末側
設定画面 →「この端末の購読を解除」

### リポジトリ側
1. 設定画面で「購読 id」を控える（16文字）
2. 「登録を削除する」から Remove push device ワークフローを開く
3. `subscription_id` に控えた id を入れて実行する

アプリをリセットした場合、端末側の購読は自動で解除されますが、リポジトリ側には残ります。忘れずに削除してください。

## 通知が届かないとき
| 確認すること | 方法 |
|---|---|
| 購読が登録されているか | Actions → Send test push を実行し、送信結果を見る |
| 購読が失効していないか | 同じ実行結果に「削除候補の購読 id」が出ていないか |
| 端末側で許可されているか | 設定画面の「通知の許可」が `granted` になっているか |
| OS側で許可されているか | 端末の設定 → 通知 で、このアプリが許可されているか |
| iPhoneでホーム画面から起動しているか | 設定画面の案内を確認 |

購読が失効していた場合は、端末で登録し直してください。ブラウザのデータを消したり、長期間アプリを開かなかったりすると失効することがあります。

## 秘密鍵を変えたとき
通知の秘密鍵（VAPID）を変えると、**登録済みの購読はすべて無効になります。** 全端末で登録し直しが必要です。

1. 新しい鍵を作る：`npm run generate:vapid`
2. 公開鍵をアプリの `runtime-config.json` と文書リポジトリの `.app/push-config.json` へ設定する
3. 秘密鍵を文書リポジトリの Secret `VAPID_PRIVATE_KEY` へ登録する
4. アプリを再デプロイする
5. `.app/push-subscriptions.json` の中身を空にする
6. 全端末で登録し直す

鍵を変える必要が生じるのは、秘密鍵が漏れたときだけです。通常は変えません。
