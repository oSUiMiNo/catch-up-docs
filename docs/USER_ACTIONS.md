# あなたが手を動かす工程

自動化できない、または権限上あなたにしかできない工程をまとめます。それぞれ「何をするか」「何を入れるか」「どう確認するか」「その後どう進むか」の順に書いています。

## U-1　アクセストークンを発行する
### 何をするか
GitHub で Fine-grained personal access token を作ります。

Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token

### 何を入れるか
| 項目 | 値 |
|---|---|
| Token name | 任意（例：`catch-up-docs`） |
| Resource owner | あなたのアカウント |
| Expiration | 任意。期限切れ時は再発行して設定画面から更新します |
| Repository access | Only select repositories |
| Selected repositories | 文書リポジトリ **1つだけ** |
| Repository permissions → Contents | **Read-only** |
| その他の権限 | すべて No access |

### どう確認するか
発行画面で、選択したリポジトリが1件であること、権限が Contents の Read-only だけであることを見てください。書き込み権限は不要です。

### その後どう進むか
アプリの初期設定画面（Step 3）でこのトークンを貼り付け、「接続テスト」を押します。成功すれば設定が保存され、一覧が表示されます。

> トークンは他人に渡さず、端末のアプリ画面へ直接入力してください。

## U-2　通知を登録する（端末ごと）
### 何をするか
アプリで購読情報を作り、それを文書リポジトリのワークフローへ貼り付けます。

アプリは文書リポジトリへ書き込みません。書き込み権限を持たせないために、この一手間が入っています。

### 何を入れるか
| 場所 | 項目 | 値 |
|---|---|---|
| アプリの通知設定画面 | 端末名 | 例：`Pixel`、`iPhone` |
| Register push device ワークフロー | `label` | 上と同じ端末名 |
| Register push device ワークフロー | `subscription_json` | アプリでコピーしたJSONをそのまま貼り付け |

### どう確認するか
ワークフローが成功し、`.app/push-subscriptions.json` が更新されていれば登録できています。続けて Send test push を実行し、端末に通知が届くことを確認してください。

### その後どう進むか
以降は、文書を追加するたびに自動で通知が届きます。詳しくは `docs/PUSH_REGISTRATION.md` を参照してください。

## U-3　Androidアプリを入れて確認する
### 何をするか
GitHub の Releases からAPKをダウンロードし、Google Play を経由せずにインストールします。

### 何を入れるか
| 場面 | 値 |
|---|---|
| インストール時 | 「この提供元のアプリを許可」をオンにする |
| 初回起動時 | アプリ専用パスワード（10文字以上） |
| 初回起動時 | 手順U-1で作ったアクセストークン |
| 通知設定 | 端末名 |

### どう確認するか
| 確認すること | 期待する状態 |
|---|---|
| 起動時の画面 | 上部にアドレスバーが**出ない** |
| 文書の閲覧 | 一覧をタップすると内容が表示される |
| ロック画面の通知 | 文書の題名やファイル名が**出ない** |
| 上書き更新 | 新しいAPKを入れても設定と既読情報が残る |

アドレスバーが出る場合は所有権の確認が通っていません。`docs/ANDROID_INSTALL.md` の確認手順を参照してください。

### その後どう進むか
確認できた項目を `docs/ACCEPTANCE_CHECKLIST.md` へ記入してください。

## U-4　iPhone・iPadで確認する
### 何をするか
Safari で公開URLを開き、共有メニューから「ホーム画面に追加」します。

### 何を入れるか
U-3 と同じく、アプリ専用パスワード、アクセストークン、端末名です。端末ごとに個別に設定します。

### どう確認するか
| 確認すること | 期待する状態 |
|---|---|
| ホーム画面から起動 | 全画面で開く |
| 通知の有効化ボタン | ホーム画面から起動したときだけ押せる |
| テスト通知 | 端末に届く |
| 文書の閲覧 | 一覧をタップすると内容が表示される |

### その後どう進むか
同じくチェックリストへ記入してください。

## U-5　鍵をバックアップする
### 何をするか
セットアップ時に生成された鍵を、安全な場所へ複製します。

### 何を入れるか
`~/.secrets/catch-up-docs/` にある次のファイルです。

| ファイル | 失った場合に起きること |
|---|---|
| `android-release.keystore` | 既存のインストールへ上書き更新できなくなる |
| `keystore-password.txt` | 同上 |
| `vapid.json` | 通知の秘密鍵。失うと全端末の再登録が必要になる |

### どう確認するか
暗号化した状態で、物理的に離れた2か所へ保管してください。パスワードマネージャの安全なメモ、暗号化した外部ストレージなどが候補です。

### その後どう進むか
この作業は一度きりです。鍵を変更したときだけやり直します。

## U-6　GitHubアカウントを保護する
### 何をするか
2要素認証またはパスキーを設定します。

### なぜ必要か
このアプリの安全性は、最終的にGitHubアカウントの安全性に依存します。アカウントが乗っ取られると、配信しているアプリを書き換えてトークンを盗むことが理屈の上では可能になります。

### どう確認するか
Settings → Password and authentication で、2要素認証が有効になっていることを確認してください。
