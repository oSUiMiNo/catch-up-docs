# 受け入れ確認

要件書の受け入れ条件 AC-001〜AC-020 と Definition of Done について、何をどう確認したかを記録します。

記号の意味：

| 記号 | 意味 |
|---|---|
| 自動 | テストまたはCIで機械的に確認済み |
| 実地 | 実際のGitHubリポジトリとワークフローで確認済み |
| 要実機 | あなたの端末での確認が必要。手順は `docs/USER_ACTIONS.md` |

## 受け入れ条件

### AC-001　文書追加から表示
**状態**：実地（通知の実配送のみ要実機）

`documents/samples/受入テスト.html` を実際に push し、Process documents ワークフローが成功、`.app/manifest.json` が2件から3件へ更新されることを確認しました。日本語のファイル名も正しく扱われています。

端末での一覧表示とタップによる閲覧は、E2E テスト `flow.spec.ts`「設定・一覧・閲覧・ロックが順に動く」で確認しています。通知の実配送は端末の購読登録後に確認してください。

### AC-002　文書の非公開性
**状態**：自動

- `scripts/verify-no-secrets.mjs` が、追跡ファイルとビルド成果物156件を検査し、トークン・秘密鍵・キーストア・文書リポジトリ名のいずれも含まないことを確認
- E2E `pwa.spec.ts`「公開資産に文書やトークンが含まれない」で、配信中のHTMLと `runtime-config.json` を実際に取得して検査
- APKには設定が含まれず、起動しても初期設定画面が出るだけ

### AC-003　認証なしアクセス拒否
**状態**：自動

E2E `flow.spec.ts`「ロック後に再読み込みしても一覧を表示しない」で、新しい状態から公開URLを開くと初期設定画面だけが出ることを確認。

### AC-004　5日境界
**状態**：自動

単体テスト `envelope.test.ts` で境界を固定しています。

| 経過時間 | 判定 |
|---|---|
| 119時間59分59秒 | 有効 |
| 119時間59分59秒999ミリ秒 | 有効 |
| 120時間00分00秒ちょうど | 期限切れ |
| 120時間00分00秒001ミリ秒 | 期限切れ |

`vault.test.ts` でも、保存済みセッションからの復元が同じ境界で切り替わることを確認しています。

### AC-005　即時ロック
**状態**：自動

E2E `flow.spec.ts`「ロック後に再読み込みしても一覧を表示しない（AC-005）」で確認。ロック後にページを再読み込みしても、パスワード入力画面だけが表示され、文書名も出ません。

### AC-006　PAT最小権限
**状態**：要実機

実装上、アプリは GET のみを行い、書き込み系のAPIを一切呼びません。統合テストで発行されるリクエストも GET だけです。実際の Contents Read-only トークンでの動作確認は、初期設定時に併せて行ってください。

### AC-007　危険HTML拒否
**状態**：実地

`script` と外部画像参照を含むHTMLを実際に push し、次を確認しました。

- Process documents ワークフローが **failure** で終了
- `.app/manifest.json` が更新されない（3件のまま、危険な文書は含まれない）
- 通知が送信されない

確認後、当該ファイルは取り除いています。

### AC-008　iframe隔離
**状態**：自動

E2E `viewerSecurity.spec.ts` で、悪意あるHTMLを実ブラウザへ渡して11項目を確認しています。Chromium と WebKit の双方で通過しています。

| 確認項目 | 結果 |
|---|---|
| script が実行されない | 通過 |
| 親のDOMが書き換えられない | 通過 |
| 最上位のURLが変わらない | 通過 |
| 外部の画像を取得しない | 通過 |
| 外部のスタイルシートを取得しない | 通過 |
| フォームが残らない | 通過 |
| `javascript:` のURLが残らない | 通過 |
| 入れ子のiframe・object・embedが残らない | 通過 |
| イベント属性が残らない | 通過 |
| iframeが完全なサンドボックスで動く | 通過 |
| 閉じると本文が残らない | 通過 |

`api.github.com` と同一オリジン以外への通信が発生しないことも、リクエスト記録から確認しています。

### AC-009　通知プライバシー
**状態**：自動（ロック画面の見え方は要実機）

単体テスト `payload.test.ts` で、通知本文に文書名・ファイル名・リポジトリ名が含まれないこと、ペイロードにも `.html` や `title` の類が現れないことを確認。

実際のロック画面での見え方は、テスト通知を受け取って確認してください。

### AC-010　Androidインストール
**状態**：要実機

署名済みAPKは GitHub Release `android-v1.0.0` に公開済みです（941,757 バイト、SHA-256 チェックサム付き）。Google Play を経由しないインストール手順は `docs/ANDROID_INSTALL.md` にあります。

### AC-011　Android TWA検証
**状態**：実地（アドレスバーの有無は要実機）

- `https://osuimino.github.io/.well-known/assetlinks.json` が HTTP 200 を返すことを確認
- そこに書かれた package ID が `io.github.osuimino.catchupdocs` であることを確認
- 署名証明書のフィンガープリントが、実際にビルドしたAPKのものと一致することを確認
  - assetlinks：`F7:05:0C:8A:...:67:60`
  - APK：`f7050c8a...67760`（apksigner の出力）

実機でアドレスバーが出ないことの確認をお願いします。

### AC-012　Android更新
**状態**：要実機

リリースワークフローは versionCode に実行番号を使い、必ず単調増加します。署名鍵と package ID は固定です。上書き更新後もデータが残ることの確認をお願いします。

### AC-013　iPhone閲覧
**状態**：要実機

手順は `docs/IOS_INSTALL.md` にあります。E2E は WebKit のモバイルビューポートでも実行する設定になっています（CIで実行）。

### AC-014　iPhone通知
**状態**：要実機

ホーム画面から起動した場合にだけ通知を有効化できるよう判定を入れています。実機での受信確認をお願いします。

### AC-015　ハッシュ不一致
**状態**：自動

- 統合テスト `githubClient.test.ts`「hash が一致しなければ本文を返さない」
- E2E `flow.spec.ts`「ハッシュが合わない文書は本文を表示しない」

どちらも、改ざんされた内容を返した場合に iframe が生成されず、エラーだけが表示されることを確認しています。

### AC-016　認証失効
**状態**：自動

E2E `flow.spec.ts`「401 なら認証の更新を促す」で、401 が返る状況で「GitHub認証を更新してください」が表示され、接続テストが通らない限り保存できないことを確認。統合テストでも401/403/404/422の分類を個別に確認しています。

エラー表示にトークンは含まれません。

### AC-017　秘密情報スキャン
**状態**：自動

単体テスト `verify-no-secrets.test.ts` で、偽のトークン文字列を検出できることを確認しています。

| 検出対象 | 結果 |
|---|---|
| Fine-grained PAT の形 | 検出する |
| Classic PAT の形 | 検出する |
| 秘密鍵のヘッダー | 検出する |
| AWSアクセスキーID | 検出する |
| 文書リポジトリ名 | 検出する（値はログに出さない） |
| 普通の文章・プレースホルダ | 検出しない |
| `.env` の実ファイル、キーストア、鍵ファイル | 検出する |
| `.env.example`、通常のソース | 検出しない |

### AC-018　文書更新
**状態**：実地

既存の `documents/welcome.html` を実際に更新して push し、次を確認しました。

- Process documents ワークフローが成功
- 「通知を送信」ステップが **skipped**（通知は送られない）
- manifest の `contentSha256` が `c8c1e9ef...` から `bfd81f86...` へ変化（既読は未読へ戻る）

### AC-019　文書削除
**状態**：実地

AC-007 の確認で追加したHTMLを削除して push し、manifest から消えること、通知が送られないことを確認しました。単体テストでも削除時の挙動を確認しています。

### AC-020　リセット
**状態**：自動

E2E `flow.spec.ts`「リセットすると初期設定へ戻る」で確認。単体テスト `vault.test.ts` でも、リセット後に未初期化状態へ戻り、古いパスワードで解除できないことを確認しています。
